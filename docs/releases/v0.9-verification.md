## 文献检索停止逻辑：新增发布阻断项（尚未实现）

### 已识别的问题

当前实现只要发现一篇论文同时缺少 DOI、PMID 和稳定 URL，就会让整批 deep-research 结果失败。该行为会丢弃同批中仍可验证的论文，不能作为 v0.9 的最终停止逻辑。

### 计划采用的规则

- 对每条记录逐一归一化并检查 DOI、PMID、稳定 URL；三者均缺失的记录从可用证据集合剔除，但必须写入 rejected-record audit；
- audit 最小字段为：原始序号、标题、DOI/PMID/URL 当前值、剔除原因、backend、run ID；
- 至少一条记录通过标识符检查时，继续 metadata、extract、evidence pack 和 audit；
- 只有全部记录不合格或没有任何可验证论文时才 fail-closed；不得静默删除或伪装合格证据；
- 规则统一适用于 Codex/Academic Research、literature-search MCP 和未来 backend。MCP 的 `identifiers`、`source_evidence`、`source_statuses` 必须先归一化，再过滤；
- 该变化只处理“候选记录是否可验证”，不降低 L1/L4/L8.5 的 section-level evidence、source metadata、review receipt 或 verification verdict 要求。

### 尚未实现与验收要求

尚未实现的代码任务包括逐条过滤、rejected-record audit 持久化、过滤后集合到后续 evidence 流程的衔接，以及零条合格记录的 fail-closed 分支。发布前必须新增单元测试、混合结果集成测试、全不合格停止测试，并完成真实 Codex/Academic Research 与 literature-search MCP 验证；同时确认现有证据门没有被放宽。

当前状态：**OPEN / RELEASE-BLOCKING**。目标表述是”保留可验证证据、审计并剔除不可验证记录、在没有任何可用证据时 fail-closed”，不是”忽略错误”或”放宽验证”。

## deep-research backend 宿主无关性：新增发布阻断项（2026-07-30）

本次验证在 Claude Code 会话中进行，但 deep-research L1 实际调用 Codex CLI，消耗 Codex 额度并撞上 OpenAI billing 限额。根因不是操作偶发，而是实现默认值：

- `deep_research.py:45-47` 的 `default_runtime_config()` 硬编码 `backend`/`executable` 为 `codex`，`skill_path` 指向 `~/.codex/skills/academic-research-suite`，不做宿主检测；
- `lifecycle.py:645` 在项目 init 时无条件写入该默认值；
- `deep_research.py:191-192`、`768-769` 与 `cli.py:410` 的 backend 集合仅 `{codex, claude}`，AntiGravity/Hermes 无法使用；
- `providers/headless.py:41-46` 已实现 `CLAUDECODE`/`CLAUDE_CODE` 宿主探测，deep-research 层未复用，导致两层行为不一致；
- `rlr_runner.yaml:6` 的 main_agent 描述已声明支持 Claude Code / Codex / AntiGravity / Hermes，与实现相矛盾。

要求：在哪个宿主中调用 RLR，就用该宿主执行 deep research；init 时检测宿主，检测不到则 fail-loud 要求显式 `--backend`，不得静默回落 Codex；`skill_path`/`plugin_dir`/skill 名称随 backend 派生。标识符校验、rejected-record audit、evidence receipt 与 fail-closed 边界仍由 RLR 统一执行，与宿主无关。

范围决定：v0.9 只支持 `{codex, claude}`。AntiGravity、Hermes 及「backend 改为可注册表」的抽象**不纳入**本次修复；若将来新增宿主再单独评估。

当前状态：**FIXED（2026-07-30）**。

修复内容：`deep_research.py` 新增 `SUPPORTED_BACKENDS` / `detect_host_backend(env=None)` / `host_matches(spec, env=None)`；`default_runtime_config(backend=None, env=None)` 按宿主派生 `executable`/`skill_path`，探测不到宿主时 fail-loud 要求 `--backend`，不再默认 codex；`cmd_deep_research_run` 在 `runtime_ready` 与任何 subprocess 之前加宿主一致性门（不一致返回 3，`--allow-host-mismatch` 显式放行）；`cmd_preflight` 接受 `--backend`；`build_invocation` 与 `runtime_ready` 的两处 backend 字面量统一到 `SUPPORTED_BACKENDS`。

已知限制：Codex 的环境标记未在真实 Codex 会话中验证，`_HOST_MARKERS` 只登记 Claude Code 的 `CLAUDECODE`/`CLAUDE_CODE`（`providers/headless.py` 依赖同一组变量）。因此 Codex 会话中 `preflight` 会 fail-loud 要求显式 `--backend codex`，而不是依赖一个未经证实的变量名。确认标记后补入 `_HOST_MARKERS` 即可，无需改逻辑。
