## 文献候选逐条过滤规则（待实现，发布前必须完成）

### 已识别的问题

当前 `validate_payload()` 对返回论文集合采用“单条记录失败即整批失败”的处理：只要一篇论文同时缺少 DOI、PMID 和稳定 URL，就立即终止整个 deep-research 任务。这会丢弃同一批中仍然可核验的论文，不符合“保留可验证证据、审计并剔除不可验证记录、没有任何可用证据时 fail-closed”的原则。

### 目标规则

1. 对每条返回记录分别检查 DOI、PMID、稳定 URL；三者全部缺失的记录进入 rejected-record audit，不进入可用证据集合。
2. 被剔除记录至少记录：原始序号、标题、DOI/PMID/URL 当前值、剔除原因、检索 backend、run ID。
3. 只要至少一条记录通过标识符边界检查，就继续 metadata、extract、evidence pack 和 audit 流程。
4. 只有在没有任何可验证论文，或所有返回论文均不合格时，才 fail-closed 并停止任务。
5. 不得静默删除、伪装合格证据或用过滤规则降低 L1/L4/L8.5 的 section-level evidence、source metadata、review receipt、verification verdict 要求；“过滤坏记录”和“放宽证据要求”是两件不同的事。
6. 该规则适用于 Codex/Academic Research、literature-search MCP 及未来 backend。backend 只提供候选结果，DOI/PMID/稳定 URL 仍由 Research Loop 统一边界校验。
7. MCP 返回 `identifiers`、`source_evidence` 或多个来源状态时，必须先统一归一化，再执行标识符过滤和 rejected-record audit。

### 尚未实现的代码任务

- 将候选归一化、逐条标识符检查、可用集合构建和 rejected-record audit 拆成可审计的边界步骤；
- 为审计记录绑定 backend、run ID、原始序号及原始标识符值，并持久化到运行产物；
- 将后续 metadata/extract/evidence pack 流程改为消费过滤后的可用集合；
- 在“零条可验证记录”时保持 fail-closed，并确保错误中包含 rejected 数量和审计路径；
- 保持统一 validator，不允许 backend 绕过本地标识符或证据门。

### 必须新增的验证

- 单元测试：混合合格/不合格记录、全部不合格、空结果、标识符空字符串/空白值、重复标识符及审计字段完整性；
- 集成测试：过滤后仍有合格记录时继续 metadata、extract、evidence pack 和 audit；零条合格记录时不生成成功 receipt；
- 真实 Codex/Academic Research 与 MCP 验证：记录 backend/run ID，核对 rejected-record audit、归一化后的 identifiers/source_evidence/source_statuses，以及 L1/L4/L8.5 原有证据门仍然生效；
- 未来 backend 复用同一边界测试，不为每个平台复制一套业务验证规则。

本规则尚未实现，属于 v0.9 发布前阻断项；在完成上述代码和验证前，不得声称文献检索停止逻辑已经调整。

## deep-research backend 宿主无关性缺陷（2026-07-30 发现，发布前应修复）

### 问题

RLR 定位为宿主无关编排器（`rlr_runner.yaml` main_agent 描述已声明支持 Claude Code / Codex / AntiGravity / Hermes），但 deep-research 执行层默认写死 Codex：

- `deep_research.py:45-47`：`default_runtime_config()` 硬编码 `backend: "codex"`、`executable: "codex"`、`skill_path` 指向 `~/.codex/skills/academic-research-suite`，无宿主检测；
- `lifecycle.py:645`：项目 init 无条件写入该默认值；
- `deep_research.py:191-192`、`768-769`：backend 白名单仅 `{codex, claude}`，AntiGravity/Hermes 直接拒绝；
- `cli.py:410`：`--backend` 同样只有两个选项；
- `providers/headless.py:41-46`：provider 层已有 `CLAUDECODE`/`CLAUDE_CODE` 宿主探测，但 deep-research 层不读取。

实际后果：在 Claude 会话中运行 RLR，deep-research 仍调用 Codex CLI，消耗错误宿主的额度，除非用户手动指定 `--backend claude`。这一后果已在真实数据验证中出现。

### 目标规则

1. 宿主一致：在哪个宿主中调用，就用该宿主执行；不得默认导向任一固定宿主。
2. init 时检测当前宿主（扩展 `providers/headless.py` 的 env 探测），检测失败时 fail-loud 要求显式 `--backend`，不得静默回落 Codex。
3. backend 由固定白名单改为可注册表，新增宿主不必修改核心校验分支。
4. `skill_path`、`plugin_dir`、skill 名称（`academic-research-suite` / `academic-research-skills` / 后续宿主对应名）随 backend 派生，不以 Codex 布局为默认。
5. 统一边界不变：DOI/PMID/稳定 URL 校验、rejected-record audit、evidence receipt 与 fail-closed 行为始终由 RLR 执行；宿主只提供候选结果。此点与上节文献过滤规则第 6 条一致。

### 必须新增的验证

- 单元测试：各宿主 env 下 init 生成的 runtime config 指向正确 backend；无法检测宿主时 fail-loud；
- 单元测试：未注册 backend 被拒绝且错误信息列出可用 backend；
- 集成测试：同一项目在不同 backend 下均能通过相同的标识符与 evidence 边界校验。

### 实施结果（2026-07-30）

状态：**FIXED**（范围限定 `{codex, claude}`；按决定不纳入 AntiGravity/Hermes，故 backend registry 抽象未做）。

- `deep_research.py` 新增 `SUPPORTED_BACKENDS`、`_HOST_MARKERS`、`detect_host_backend(env=None)`、`host_matches(spec, env=None)`；`default_runtime_config()` 改为 `default_runtime_config(backend=None, env=None)`，按宿主派生 `executable`/`skill_path`，探测不到宿主时抛 `DeepResearchError` 并提示 `--backend`。
- `build_invocation` 与 `runtime_ready` 中两处 `{"codex","claude"}` 字面量改为引用 `SUPPORTED_BACKENDS`，消除多份真相。
- `cmd_deep_research_run` 在 spec 解析之后、`runtime_ready` 与任何 subprocess 之前加宿主一致性门；不一致返回 3，`--allow-host-mismatch` 显式放行。
- `cmd_preflight` 接受 `--backend`；生成 claude 配置时提示 `plugin_dir` 需人工填写（不臆造安装路径，由既有 `runtime_ready` 报缺失）。

未做且需知悉的限制：**Codex 未验证出可靠的环境标记**，`_HOST_MARKERS` 只登记了 Claude Code 的 `CLAUDECODE`/`CLAUDE_CODE`（`providers/headless.py` 依赖同一组变量）。因此 Codex 会话中 `preflight` 会 fail-loud 要求显式 `--backend codex`，而不是猜一个未经证实的变量名。在真实 Codex 会话中确认标记后可补入该表，无需改动逻辑。

实际验证：`python -m pytest tests/test_deep_research.py tests/test_cli_standalone_imports.py -q` → 39 passed；全量 `python -m pytest -q` → 392 passed / 0 failed；`python -m pytest --cov=research_loop -q` → TOTAL 68%（未下降），`deep_research.py` 77%。

真实会话冒烟（本次在 Claude Code 中执行）：`detect_host_backend()` 返回 `claude`，`default_runtime_config()` 生成 `backend/executable = claude`；对 `.v09-realdata-native-v21-catalog1`（配置为 codex）执行 `deep-research-run --node L1`，在启动任何子进程前被拦下并返回 3 —— 即本次事故场景已封堵。

## 后续可加入的 AI4AI 改进（不改变当前优先级）

这不是新的自动化科学决策系统，而是让后续工程改进更可控。

- **优化合同：** 每次优化前声明目标、允许修改范围、禁止修改范围、资源上限和人工升级条件。
- **两层经验：** 账本继续保存原始事实；单独的经验记录保存“为什么成功或失败”、适用条件和失效时间。
- **实际可见上下文收据：** 除原始资料外，记录模型真正收到的摘要、截断结果、prompt/template 版本和 context manifest。
- **人工升级出口：** 对高风险、证据冲突、跨版本资料缺失等情形输出 `ESCALATE`，由人决定。

这些能力只能优化提示、工具、上下文和工程 harness；不得让 agent 自行改变 schema、topology、gate、迁移规则或科学结论。
