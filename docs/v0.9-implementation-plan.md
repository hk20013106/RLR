## 发布阻断项 1：文献候选逐条过滤规则

当前 `validate_payload()` 对返回论文集合采用"单条记录失败即整批失败"。目标：对每条记录分别检查 DOI/PMID/稳定 URL，三者全缺的进 rejected-record audit，至少一条合格则继续，全不合格才 fail-closed。

**尚未实现：**

- 逐条归一化 + 标识符检查 + 可用集合构建 + rejected-record audit 拆成可审计边界步骤
- 审计记录绑定 backend、run ID、原始序号、原始标识符值，持久化到运行产物
- 后续 metadata/extract/evidence pack 改为消费过滤后的可用集合
- 零条可验证记录时 fail-closed，错误包含 rejected 数量和审计路径
- 不允许 backend 绕过本地标识符或证据门

**必须新增的测试：**

- 混合合格/不合格、全不合格、空结果、标识符空字符串/空白值、重复标识符
- 过滤后仍有合格记录时继续完整 evidence 流程
- 零条合格时不生成成功 receipt
- 真实 Codex/ARS 与 MCP 验证：核对 rejected-record audit 和 L1/L4/L8.5 证据门未放宽
